# TRINITY — CHANGELOG

## 4.0 (в работе) — шаг A: утверждённые правила (2026-11-13)
Решения пользователя: SPEC_4.0.md, раздел A.

### Добавлено
- `risk/profiles.py`: единственный профиль **BALANCED** (0,75% / 3% / 3% / 6% / 10–12–15–20%, качество ≥ 70);
  конфигурация с другими значениями не загружается; замороженные модели лимитов; проверка целостности
  профиля перед каждым ордером (событие `PROFILE_INTEGRITY`).
- `ai/quality_score.py`: Trade Quality Score 0–100 по фактическим данным; порог в Risk Engine
  (вход без оценки или ниже порога отклоняется); пороги по ботам только ≥ 70.
- Журнал сигналов: таблица `signals` (оценка, факторы, решение), колонка `orders.quality_score` (миграция 004).
- `core/position_guardian.py`: независимый страж стопов (каждые 15 с, во всех режимах): защитные выходы,
  отмена мешающих лимитных тейков, аварийные стопы, контроль связи (потеря/восстановление).
- Аварийный протокол HOLD_PROTECTED для `/emergency_stop`.
- `notifications/confirmations.py`: двухшаговые подтверждения в Telegram (`/resume`, `/stop` →
  `/confirm <код>`, `/cancel`); коды одноразовые, 120 с, привязаны к пользователю, 3 попытки.
- `/resume` выполняет пять проверок (связь, защищённость позиций, Risk Engine, критические ошибки,
  сверка балансов) на шаге 1 и повторно при подтверждении.
- `run_live.py`: двухшаговое подтверждение перехода в LIVE (фраза + одноразовый код после сводки).
- Документы: SPEC_4.0.md, RISK_MANAGEMENT.md (RISK_POLICY.md теперь ссылка), этот CHANGELOG.

### Изменено
- Пауза (`/pause`, `/stop`, аварийный режим) запрещает только новые входы; цикл ботов продолжает
  сопровождать открытые позиции. Раньше пауза останавливала цикл бота целиком.
- Аварийный режим разрешает сокращающие выходы (раньше блокировал все ордера, включая защитные стопы).
- Crypto Momentum: признак ADX; оценка качества и журнал сигналов для каждого кандидата.
- Stock Trend: оценка качества и журнал сигналов (повторные одинаковые оценки за день пишутся один раз).

### Исправлено
- Открытые позиции оставались без сопровождения после `/stop` и `/emergency_stop`.
- Выставленный тейк-профит мешал защитному выходу по стопу при обвале.
