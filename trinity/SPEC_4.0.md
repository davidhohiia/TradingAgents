# TRINITY 4.0 — техническое задание (актуальная редакция)

Базовая версия: TRINITY 3.0, коммит `0593fef` (191 тест зелёный). Полный текст исходного ТЗ 4.0
предоставлен пользователем; ниже — утверждённые решения, которые имеют приоритет над исходным текстом,
и статус выполнения этапов.

## A. Утверждённые решения (2026-11-13)

### A1. Перезапуск и реальная торговля
* После **любого** перезапуска (сбой, перезагрузка Windows, ручной перезапуск) система запускается
  **только в PAPER**. Независимо от `.env`, сохранённых разрешений и состояния до перезапуска.
* LIVE включается **только вручную** через `scripts/run_live.py` с двухшаговым подтверждением.
* Автоматическое возобновление LIVE **запрещено**. Настройки вида `LIVE_AUTORESUME` не существует.
* При старте: подключение к площадкам → балансы → открытые ордера → позиции → сверка с SQLite →
  восстановление состояния → проверка Risk Engine. При неуспешной сверке торговля блокируется
  (`recovery_lock`), защитное управление открытыми позициями продолжается.

### A2. Telegram: подтверждения
| Команда | Подтверждение | Поведение |
|---|---|---|
| `/pause` | нет, мгновенно | запрет новых позиций; открытые позиции продолжают управляться (стопы, тейки, выходы) |
| `/emergency_stop` | нет, мгновенно | **аварийный протокол** (A3) |
| `/resume` | **двухшаговое** | шаг 1 — пять проверок; при успехе выдаётся одноразовый код; шаг 2 — `/confirm <код>`, проверки повторяются, затем снимается только пауза |
| `/stop` | **двухшаговое** | шаг 1 — описание последствий и код; шаг 2 — `/confirm <код>`: запрет входов, отмена неисполненных входных ордеров, позиции остаются под защитой |
| Переход в LIVE | **двухшаговое** | только локально `run_live.py`: (1) фраза `START LIVE TRADING`, (2) сводка + одноразовый код. Telegram LIVE не включает |

Коды: 6 цифр, одноразовые, действуют 120 секунд, привязаны к пользователю Telegram; после 3 неверных
попыток запрос аннулируется; `/cancel` отменяет запрос. Все команды — только для разрешённых user ID.

Проверки `/resume`: (1) подключение к каждой площадке; (2) состояние открытых позиций (у каждой есть
стоп, цена свежая); (3) Risk Engine: нет блокировок, кроме паузы (дневная/недельная/просадка/аварийная
пауза паузой не снимаются); (4) нет критических ошибок исполнения после постановки на паузу и нет
открытых circuit breaker; (5) синхронизация фактического баланса — успешная сверка с площадкой.

### A3. Аварийный протокол `/emergency_stop` (HOLD_PROTECTED)
Выполняется немедленно, без подтверждения, в таком порядке:
1. Флаг `emergency_stop` в Risk Engine — с этого момента любые **новые позиции** отклоняются.
   Разрешены только ордера на **сокращение** существующих позиций (стоп, тейк, выход по стратегии).
2. У всех ботов отключаются входы; боты продолжают управлять открытыми позициями.
3. Отменяются все **неисполненные входные (BUY) ордера** — их отмена безопасна. Выходные ордера
   (уже выставленные тейки) сохраняются, так как только уменьшают риск.
4. Каждой открытой позиции гарантируется защитный стоп: если стопа нет, назначается аварийный стоп
   `last_price × (1 − emergency.default_stop_pct)` (по умолчанию 3%).
5. Включается **Position Guardian** (работает всегда, раз в 15 секунд, независимо от ботов): при цене
   bid ≤ стопа отправляет защитный рыночный выход через Execution Engine и Risk Engine; повторяет отмену
   входных ордеров, которые не удалось отменить (например, при обрыве связи); при недоступности
   площадки сообщает, что позиция временно не может быть закрыта, и продолжает попытки.
6. В Telegram отправляется отчёт: сколько ордеров отменено, список позиций со стопами, что не удалось.
7. Позиции **не ликвидируются** по рынку автоматически. Снятие аварийного режима — только локально
   (`scripts/emergency_stop.py --clear`).

### A4. Профиль BALANCED (единственный)
| Параметр | Значение |
|---|---|
| Риск на сделку | 0,75% капитала |
| Совокупный открытый риск | 3% |
| Дневной лимит убытка | 3% |
| Недельный лимит убытка | 6% |
| Предупреждение по просадке | 10% |
| Снижение активности | 12% |
| Остановка LIVE | 15% |
| Аварийный порог | 20% |
| Минимальный Trade Quality Score | 70 |

* Других профилей нет. Конфигурация, расходящаяся с профилем, **не загружается**.
* Порог качества для отдельного бота можно только **повысить** (≥ 70), понизить нельзя.
* Лимиты неизменяемы во время работы (замороженные модели). Risk Engine перед каждым ордером проверяет
  целостность профиля; при расхождении все новые позиции блокируются и создаётся критическое событие.
* Ни AI-модули, ни Telegram, ни автоматика не имеют пути изменения этих значений. Изменение возможно
  только правкой кода профиля с повторным прохождением тестов (хеш кода участвует в допуске к LIVE).

## C. Неизменные правила
Сохранение капитала → контроль риска → качество сделок → стабильность → доходность → удобство.
Без мартингейла, без автоматического плеча и увеличения риска, без фиктивных данных, без обещаний
доходности, без автоматического включения LIVE.
