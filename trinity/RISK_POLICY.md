# TRINITY 3.0 — политика управления рисками (Aggressive Growth Edition)

Ни один бот и ни один AI-модуль не может изменить или обойти эти правила: торговые адаптеры есть
только у `ExecutionEngine`, а он вызывает `RiskManager.check_order` **перед каждым ордером**.
AI-модули (анализ рынка, деградация, рекомендации) только сообщают — параметры не меняют.
Параметры — `config/strategies.yaml` (разделы `risk`, `leverage`, `capital`), валидируются при запуске.

> «30% в месяц» — **только информационный ориентир**. Он не используется для открытия сделок,
> расчёта размеров или ослабления лимитов. Сделки ради достижения цели не открываются. Доходность не гарантируется.

## Капитал

| Параметр | Значение |
|---|---|
| Начальный капитал | $500 (записан как первое пополнение) |
| Crypto Momentum / Stock Trend / Arbitrage | $150 / $100 / $0 |
| Резерв | $250 — никогда не используется автоматически |
| Ежемесячное пополнение | $200 → **всегда в резерв** |
| Реинвестирование | 100%: реализованная прибыль увеличивает капитал стратегии, убыток уменьшает |
| Максимум на одну стратегию | 45% внесённого капитала |

* Пополнения — **не доход**: капитал = внесено + чистый реализованный/нереализованный PnL;
  пик, дневная и недельная база сдвигаются на сумму пополнения (пополнение не скрывает просадку).
* Месячная доходность — по методу Modified Dietz (пополнения исключены).
* Перераспределение резерва: только предложение (≥ 30 сделок, PF ≥ 1.2, прибыль > 0, нет деградации,
  нет блокировок, просадка < 10%) **и** ручное подтверждение `scripts/capital.py --approve ID`.
  Арбитраж капитал не получает. В LIVE деньги на биржу/брокеру переводите сами.

## Проверки перед каждым ордером

Проценты — от **текущего капитала счёта**.

| Проверка | Лимит |
|---|---|
| Риск сделки (вход − стоп) × кол-во | ≤ 0.75% (× 0.5 при просадке ≥ 12%) |
| Суммарный открытый риск (позиции + ожидающие входы) | ≤ 3% (× 0.5 при просадке ≥ 12%) |
| Общая экспозиция | ≤ 60% капитала |
| Статическая группа корреляции (крипто / акции США) | ≤ 35% капитала |
| Динамическая корреляция доходностей ≥ 0.80 с открытой позицией | вход запрещён (одна позиция на кластер) |
| Тот же инструмент у другой стратегии | запрещено |
| Ордер / позиция в инструменте | ≤ $120 / ≤ 60% капитала стратегии |
| Открытых позиций / ордеров | ≤ 5 / ≤ 30 |
| Свежесть данных | крипто 30 с, акции 180 с |
| Circuit breaker API | 5 ошибок подряд → пауза 120 с |
| Шорт | запрещён (продажа ≤ свободной позиции) |
| Плечо для акций | запрещено всегда |
| Плечо для крипто | только через LeverageGuard (см. ниже) |

## Лимиты потерь и уровни просадки

| Событие | Реакция |
|---|---|
| Дневной убыток 3% (от капитала на начало суток UTC) | новые входы блокируются до следующих суток, неисполненные входы отменяются |
| Недельный убыток 6% (от начала ISO-недели) | то же до следующей недели |
| Просадка 10% | предупреждение в Telegram |
| Просадка 12% | **сниженная активность**: риск сделки и открытый риск × 0.5 |
| Просадка 15% | **блокировка**: новые позиции (реальные и виртуальные) запрещены, LIVE отключается, неисполненные ордера отменяются, позиции не ликвидируются (защитные стопы работают), подробное сообщение в Telegram со списком позиций, снятие — `emergency_stop.py --confirm-drawdown` |
| Просадка 20% | **жёсткая остановка**: только защитные выходы; снятие — отдельно `emergency_stop.py --clear-hard-stop` |

`/resume` снимает только паузу. Аварийная остановка (`/emergency_stop`) блокирует все ордера,
снимается только локально. После любого снятия блокировки LIVE снова требует `run_live.py`.

## Ограниченное кредитное плечо

По умолчанию **выключено** (`LIVE_LEVERAGE_ENABLED=false`, `leverage.enabled: false`). Не используется
в paper-режиме и на этапе первоначальной реальной торговли. Разрешение (LeverageGuard) требует **всех** условий:

1. `LIVE_LEVERAGE_ENABLED=true` + фраза `LEVERAGE_ACKNOWLEDGEMENT`;
2. `leverage.enabled: true`;
3. ≥ 60 дней реальной торговли **без плеча**, чистый результат > 0, 0 критических ошибок исполнения;
4. полный набор тестов пройден на текущем коде;
5. локальное одобрение `scripts/leverage.py --approve` (фиксирует максимум; повышение — только новым одобрением).

Ограничения при разрешении: изолированная маржа; только BTC/USDT и ETH/USDT; начальный предел 1.5x,
абсолютный программный предел 2x (конфиг выше 2x не загрузится); плечо не повышается автоматически;
перед каждым ордером рассчитывается ликвидационная цена, стоп должен быть выше ликвидации с запасом
(≥ 50% расстояния вход→ликвидация); при funding > 0.05%/8ч или неизвестном funding вход запрещён;
funding начисляется на позицию ежечасно; цена в пределах 5% от ликвидации → критическое уведомление.
Плечо **не увеличивает риск сделки** (0.75%) — оно лишь уменьшает требуемую маржу.

## Что НЕ защищено

Гэпы через стоп (особенно акции между сессиями), отказ биржи исполнить выход, депег USDT,
отключение ПК/интернета, расхождение оценочных комиссий, принудительная ликвидация при резком
движении между проверками (при включённом плече). Эти риски остаются у пользователя.
