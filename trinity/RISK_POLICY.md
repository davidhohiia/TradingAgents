# TRINITY — политика управления рисками

Ни один бот и ни один AI-модуль не может обойти эти правила: биржевые адаптеры с правом торговли
есть только у `ExecutionEngine`, а он вызывает `RiskManager.check_order` **перед каждым ордером**.
Все параметры — в `config/strategies.yaml` (раздел `risk`) и валидируются при запуске.

## Капитал

| Параметр | Значение |
|---|---|
| Общий капитал | $500 |
| Crypto Grid / Stock Trend / Arbitrage | $150 / $150 / $0 |
| Резерв | $200 — никогда не используется автоматически |
| Реинвестирование прибыли | запрещено (прибыль не увеличивает бюджет; убытки уменьшают) |

Аллокатор не допускает превышения бюджета, двойного резервирования одного ордера, отрицательного
доступного остатка. Источник истины — БД (позиции + активные ордера), поэтому после сбоя распределение
восстанавливается точно.

## Проверки перед каждым ордером

* аварийная остановка / блокировки (восстановления, просадки, дневная, пауза), LIVE отключён;
* корректность количества/цены, рынок активен, данные не устарели (крипто 30 с, акции 180 с);
* circuit breaker биржи (5 ошибок подряд → пауза 120 с), биржа подключена;
* частота ордеров ≤ 20/мин, открытых ордеров ≤ 30; лимитная цена в пределах 3% от рынка;
* **продажи**: не больше свободной позиции (шорт запрещён);
* **покупки**: минимальный размер; ордер ≤ $75; бюджет стратегии; обязателен защитный стоп ниже входа;
  риск `qty × (вход − стоп)` ≤ 1% капитала стратегии; общая экспозиция (позиции + ожидающие покупки)
  ≤ 60% от $500; группа корреляции (BTC+ETH, SPY+QQQ+VTI) ≤ 30% от $500; позиция в инструменте
  ≤ 60% капитала стратегии; открытых позиций ≤ 6;
* дубликаты: тот же `client_order_id`, тот же ордер по той же цене, встречный ордер другой стратегии (self-trade).

## Размер позиции

`qty = (капитал стратегии × риск%) / |вход − стоп|`, затем ограничения (макс. ордер, макс. позиция,
доступные деньги), округление **вниз** к шагу лота. Сетка: фиксированный размер уровня ($20), при
необходимости уменьшается под лимит риска. Мартингейл и увеличение после убытков невозможны.

## Дневной лимит убытка — 2% ($10)

Дневной PnL = капитал сейчас (реализованный + нереализованный) − капитал на начало суток UTC.
При достижении: блок новых входов (разрешены только сокращающие ордера), отмена неисполненных
покупок, позиции сохраняются, уведомление в Telegram. Снимается автоматически в новые сутки UTC.

## Максимальная просадка — 8% от пика

Предупреждение на 5%. На 8%: блок торговли (разрешены только защитные выходы), LIVE отключается,
**все** неисполненные ордера отменяются, позиции **не** ликвидируются по рынку, уведомление.
Пик хранится в БД. Снятие — только локально после проверки:
`python trinity/scripts/emergency_stop.py --confirm-drawdown` (ввод фразы `CONFIRM DRAWDOWN REVIEW`),
затем LIVE снова требует полного прохождения `run_live.py`.

## Аварийная остановка

`/emergency_stop` или `scripts/emergency_stop.py`: немедленно блокирует **все** новые ордера (включая
выходы), отменяет открытые ордера (из Telegram), позиции не трогает. Снимается только локально:
`emergency_stop.py --clear` (ввод `CLEAR EMERGENCY STOP`). `/resume` её не снимает.

## Сбои API

Повторы с экспоненциальной задержкой только для идемпотентных запросов; создание ордера не
повторяется вслепую (поиск по `client_order_id`). Неизвестный исход → `PENDING_SUBMIT`, разрешается
сверкой; не найден за 2 мин → `FAILED`. Circuit breaker блокирует новые ордера на проблемной бирже.

## Режимы рынка (Crypto Grid)

В режимах `bear`, `strong_bear`, `high_volatility` сетка отменяет неисполненные покупки и не открывает
новые; существующие лоты сохраняют тейк-профиты и стоп сетки. Лимит запаса $60 на инструмент
предотвращает бесконечное усреднение. После срабатывания стопа — пауза 4 часа.

## Что НЕ защищено

Гэпы цены через стоп (особенно акции между сессиями), отказ биржи исполнить выход, депег USDT,
отключение ПК/интернета во время открытых позиций, ошибки в комиссиях-оценках. Эти риски остаются у пользователя.
