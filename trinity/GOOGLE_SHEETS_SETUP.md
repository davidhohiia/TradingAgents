# Google Sheets — Trading Journal: настройка

TRINITY ведёт журнал сделок в Google Таблице **«TRINITY 3.0 — Trading Journal»** через официальный
Google Sheets API v4. SQLite остаётся основной базой; таблица — дополнительный журнал и отчётность.
Торговля **не зависит** от доступности Google: при любых проблемах записи копятся локально и
отправляются автоматически, когда связь восстановится.

> Названия пунктов в Google Cloud Console периодически меняются. Если что-то выглядит иначе —
> ориентируйтесь на официальную документацию: https://developers.google.com/sheets/api/quickstart/python

## 1. Создайте проект Google Cloud

1. Откройте https://console.cloud.google.com/ и войдите в свой аккаунт Google.
2. Вверху выберите список проектов → **New Project** → имя, например `trinity-journal` → **Create**.
3. Убедитесь, что выбран новый проект.

## 2. Включите Google Sheets API

**APIs & Services → Library** → найдите **Google Sheets API** → **Enable**.

## 3. Выберите способ авторизации

### Вариант A — Service Account (рекомендуется для круглосуточной работы)

1. **APIs & Services → Credentials → Create credentials → Service account**. Имя: `trinity-journal`.
   Роли проекту назначать не нужно.
2. Откройте созданный аккаунт → вкладка **Keys → Add key → Create new key → JSON**. Скачается файл ключа.
3. Сохраните его **вне репозитория** или в `trinity/secrets/` (папка исключена из git), например
   `trinity/secrets/google-service-account.json`. Никому его не пересылайте и не коммитьте.
4. Скопируйте e-mail сервисного аккаунта (вида `trinity-journal@<project>.iam.gserviceaccount.com`).
5. **Создайте таблицу сами**: https://sheets.new → назовите `TRINITY 3.0 — Trading Journal` →
   **Share (Настройки доступа)** → вставьте e-mail сервисного аккаунта → роль **Editor (Редактор)**.
   (Сервисные аккаунты обычно не могут сами владеть файлами на Google Диске, поэтому таблицу
   создаёте вы и делитесь ею.)
6. Скопируйте ID таблицы из адреса: `https://docs.google.com/spreadsheets/d/`**`<ID>`**`/edit`.

### Вариант B — OAuth 2.0 (от имени вашего аккаунта)

1. **APIs & Services → OAuth consent screen**: тип **External**, заполните название приложения,
   в **Test users** добавьте свой e-mail.
2. **Credentials → Create credentials → OAuth client ID → Desktop app** → скачайте JSON клиента в
   `trinity/secrets/client_secret.json`.
3. В `.env` укажите `GOOGLE_OAUTH_CLIENT_SECRET_FILE` и `GOOGLE_OAUTH_TOKEN_FILE`
   (например `trinity/secrets/google-oauth-token.json`), затем один раз выполните
   ```
   python trinity/scripts/sheets.py --oauth-setup
   ```
   Откроется браузер для подтверждения доступа; токен сохранится в указанный файл.
4. ID таблицы можно не указывать — TRINITY сама создаст таблицу «TRINITY 3.0 — Trading Journal»
   в вашем Google Диске и запомнит её ID.

## 4. Настройте `.env`

```
GOOGLE_SHEETS_ENABLED=true
GOOGLE_SHEETS_SPREADSHEET_ID=<ID таблицы>          # обязательно для варианта A
GOOGLE_SERVICE_ACCOUNT_FILE=trinity/secrets/google-service-account.json   # вариант A
# GOOGLE_OAUTH_CLIENT_SECRET_FILE=trinity/secrets/client_secret.json      # вариант B
# GOOGLE_OAUTH_TOKEN_FILE=trinity/secrets/google-oauth-token.json         # вариант B
GOOGLE_SHEETS_TIMEZONE=Europe/Amsterdam
GOOGLE_SHEETS_SYNC_INTERVAL_SECONDS=60
```

Права доступа используются минимальные: scope `https://www.googleapis.com/auth/spreadsheets`.

## 5. Проверьте соединение

```
python trinity/scripts/sheets.py --check     # доступ к таблице; создаёт недостающие листы и заголовки
python trinity/scripts/sheets.py --sync      # отправить накопленные сделки и обновить статистику
python trinity/scripts/sheets.py --status    # сколько записей ждёт отправки, последняя ошибка
python trinity/scripts/sheets.py --errors    # журнал ошибок синхронизации
```
При каждом запуске `run_paper.py`/`run_live.py` соединение проверяется автоматически; результат —
в логе. В Telegram: `/journal`.

## 6. Что записывается

**Trades** — одна строка на каждую **полностью закрытую** сделку (цикл позиции от первого входа до
полного выхода). Частичные исполнения ордеров и несколько ордеров на вход/выход объединяются в одну
сделку: цены — средневзвешенные по фактическим исполнениям, комиссии — сумма фактических комиссий.

| № | Столбец | Источник |
|---|---|---|
| 1 | ID сделки | уникальный, постоянный (`P-`/`L-` + инструмент + время открытия + хеш) |
| 2 | Название бота | Crypto Momentum AI / Stock Trend AI |
| 3 | Торговый инструмент | |
| 4 | Направление | LONG (TRINITY открывает только длинные позиции; формула SHORT реализована и протестирована) |
| 5–6 | Цена покупки / продажи | средневзвешенные по исполнениям, без комиссий |
| 7–10 | Дата/время покупки и продажи | Europe/Amsterdam (с учётом летнего времени) |
| 11 | Количество актива | закрытое количество |
| 12 | Комиссия | сумма комиссий входа и выхода (USD) |
| 13 | Прибыль/убыток (USD) | **чистая**: валовая − комиссии − funding |
| 14 | Прибыль/убыток (%) | чистая / задействованный капитал × 100 |
| 15 | Стратегия | momentum / breakout / trend |
| 16 | Статус сделки | `CLOSED` (реальная) или `CLOSED (VIRTUAL)` (paper) |
| 17 | Причина закрытия | stop loss, take profit, trailing stop, … |
| 18+ | Валовая прибыль, Funding, Задействованный капитал, Плечо, Режим, число частичных входов/выходов | |

Формулы: LONG — валовая = (цена продажи − цена покупки) × количество; SHORT — (цена входа − цена
выхода) × количество; чистая = валовая − все комиссии − funding; задействованный капитал =
цена входа × количество / плечо.

**Daily Statistics** — по дням (Europe/Amsterdam): количество сделок, прибыль, убыток, чистый результат,
доходность за день (к балансу на начало дня), баланс портфеля на конец дня. Если записанного баланса нет,
ячейка остаётся пустой — значения не придумываются.

**Bot Statistics** — по ботам и подстратегиям: всего, прибыльных, убыточных, Win Rate, средняя
прибыль, средний убыток, общая прибыль, общий убыток, чистый результат, чистая доходность (к капиталу бота).

**Portfolio** — начальный депозит, пополнения, текущий баланс, свободные средства, средства в
позициях, общая прибыль/убыток (без пополнений), доходность %, текущая просадка, резерв, время обновления.

Листы статистики перестраиваются из SQLite при каждой синхронизации, поэтому правки вручную в них
будут перезаписаны. Лист Trades только дополняется.

## 7. Надёжность

* Закрытая сделка записывается в SQLite (`journal_trades`) и в очередь отправки (`sheets_outbox`)
  **в одной транзакции** с исполнением — ничего не теряется при отключении интернета или перезапуске.
* Перед отправкой читаются ID, уже имеющиеся в листе Trades: даже если ответ Google потерялся после
  успешной записи, строка не задублируется.
* Повторы с экспоненциальной задержкой при 429/5xx/сетевых ошибках; при 401 токен обновляется.
  Ошибки 403/404 (нет доступа, неверный ID) не повторяются бесконечно — смотрите `--errors`.
* Каждая ошибка сохраняется в `sync_errors`; уведомление в Telegram — не чаще раза в сутки.
* PAPER-сделки помечены `CLOSED (VIRTUAL)` и режимом PAPER — их нельзя спутать с реальными.
  Листы статистики показывают текущий режим работы (указан на листе Portfolio).

## 8. Безопасность

* Ключи и токены — только в файлах вне git (`trinity/secrets/` игнорируется) и путях в `.env`.
* Не публикуйте таблицу «для всех, у кого есть ссылка», если в ней реальные суммы.
* Отозвать доступ: удалите ключ сервисного аккаунта в Cloud Console или уберите аккаунт из
  доступа к таблице; для OAuth — https://myaccount.google.com/permissions.
