# Развёртывание на Windows 10/11 и работа 24/7

## 1. Установка Python
* Скачайте Python 3.12 (64-bit) с https://www.python.org/downloads/windows/.
* В установщике отметьте **Add python.exe to PATH**. Проверка: `py -3.12 --version`.

## 2. Виртуальное окружение и зависимости
```powershell
cd C:\path\to\repo
powershell -ExecutionPolicy Bypass -File trinity\scripts\windows\install.ps1
```
Вручную: `py -3.12 -m venv trinity\.venv`, `trinity\.venv\Scripts\python.exe -m pip install -r trinity\requirements.txt`.

## 3. Настройка .env
`copy trinity\.env.example trinity\.env`, затем `notepad trinity\.env`. Установщик ограничивает права
на файл текущим пользователем. Не храните `.env` в облачных папках с общим доступом.

## 4. Инициализация БД
`trinity\.venv\Scripts\python.exe trinity\main.py --init-db` → `trinity\data\trinity.db`.

## 5. Telegram
См. README §6.

## 6. Запуск
* PAPER: `trinity\scripts\windows\start_paper.bat` (сам перезапускает движок через 30 с после сбоя;
  код выхода 2 = уже запущен второй экземпляр — повторов нет).
* Панель: `trinity\scripts\windows\start_dashboard.bat` → http://127.0.0.1:8501.
* LIVE: `start_live.bat` — только вручную, с подтверждением в консоли.

## 7. Автоматический запуск
```powershell
powershell -ExecutionPolicy Bypass -File trinity\scripts\windows\register_autostart.ps1
```
Создаёт задачи планировщика: `TRINITY-Paper` (при входе, перезапуск при остановке, без дублирования
экземпляров) и `TRINITY-Backup` (ежедневно 03:17). Автозапуск **всегда PAPER**.
Чтобы задача работала без входа в систему, в «Планировщике заданий» включите
«Выполнять для всех пользователей» (потребуется пароль Windows).

Docker Desktop (альтернатива): `docker compose -f trinity/docker-compose.yml up -d --build` — тоже только PAPER.

## 8. Логи и их ротация
`trinity\logs\trinity.jsonl` — JSON-логи, ротация в полночь UTC, хранится 30 файлов;
`trinity\logs\errors.log` — ошибки, 5 файлов по 5 МБ. Секреты маскируются.

## 9. Резервное копирование и восстановление
Движок делает копию каждые 6 ч, задача Windows — ежедневно; хранятся 14 последних в `trinity\data\backups`.
Скопируйте эту папку на внешний диск/в облако по своему расписанию.
Восстановление: остановите движок → `python trinity\scripts\backup.py --restore <файл>` → запустите;
торговля останется заблокированной до успешной сверки.

## 10. Что обрабатывает система
| Ситуация | Поведение |
|---|---|
| обрыв интернета / тайм-аут API | повторы с задержкой, circuit breaker, статус `CONNECTION ERROR`, ордера на этой бирже блокируются |
| лимит частоты запросов | `enableRateLimit` в CCXT, увеличенная задержка при 429 |
| временная недоступность биржи | боты продолжают попытки, другие боты работают |
| ошибка БД / повреждение файла | integrity check, восстановление из бэкапа, блокировка до сверки |
| второй экземпляр | блокировка процесса (`data\trinity.lock`), второй завершится с кодом 2 |
| неожиданное завершение | write-ahead ордеров + сверка при старте; при расхождении — блокировка |
| перезагрузка ПК | автозапуск в PAPER; LIVE не возобновляется автоматически |

## 11. Что может прервать работу (и как снизить риск)
Спящий режим, обновления Windows с перезагрузкой, отключение питания и интернета **останавливают**
систему: пока она не работает, стопы не отслеживаются, и цена может уйти дальше стопа.

Рекомендации для максимально стабильной работы:
* Параметры электропитания → «Сон: никогда», отключить гибернацию: `powercfg /hibernate off`;
  для ноутбука — работа от сети, «при закрытии крышки: ничего не делать».
* Windows Update → «Период активности» на часы торговли; «Приостановить обновления» перед важными периодами;
  после перезагрузки проверьте `/status`.
* ИБП (источник бесперебойного питания) для ПК и роутера; проводное подключение к интернету;
  при возможности — резервный мобильный канал.
* Исключите папку проекта из облачной синхронизации (блокировки файлов SQLite).
* Синхронизация времени Windows включена (точное время важно для проверки свежести данных).
* Telegram-уведомления включены: watchdog сообщит о зависших ботах, ошибках API и нехватке диска.
* Для настоящей круглосуточной работы надёжнее VPS/выделенный сервер (Linux + Docker), чем домашний ПК.
